# 비-sargable 조건 (컬럼에 함수/암묵적 형변환)

인덱스가 있어도 WHERE 절에서 컬럼을 함수로 감싸거나 암묵적 형변환이 일어나면 인덱스를 타지 못한다.

- **암묵적 형변환**: `WHERE emp_id = '1001'` 인데 `emp_id`가 NUMBER면 Oracle이 내부적으로
  `TO_NUMBER`/`TO_CHAR` 변환을 끼워 넣어 인덱스를 못 쓰거나 예상치 못한 결과를 낸다.
- **LIKE 선행 와일드카드**: `LIKE '%KIM'`처럼 앞에 `%`가 오면 일반 B-Tree 인덱스 레인지 스캔이 불가능하다
  (`LIKE 'KIM%'`처럼 뒤에만 와일드카드가 오는 경우만 인덱스 레인지 스캔 가능).
- **OR 조건과 인덱스**: `WHERE a = 1 OR b = 2`처럼 서로 다른 컬럼에 대한 OR은 각 컬럼 인덱스를
  개별적으로 다 타지 못하고 풀스캔으로 빠지기 쉽다.

## 개선안
1. 데이터 타입을 애초에 일치시키거나, 애플리케이션 레벨에서 바인드 변수 타입을 정확히 맞춘다.
2. 함수형 조건은 함수 기반 인덱스로, 선행 와일드카드 LIKE는 텍스트 인덱스(Oracle Text)나
   역순 인덱스(reverse) 검토, 혹은 애초에 검색 요구사항 재정의를 고려한다.
3. OR 조건은 `UNION ALL`로 분리해 각각 인덱스를 타게 재작성하는 것을 고려한다.
